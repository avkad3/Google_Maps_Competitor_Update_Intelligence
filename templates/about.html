How it works

From competitor list to ready-to-post Google Maps updates.

Workflow

  1. Create a project with your own Google Maps profile and optional search keywords.
  2. Add competitors manually (or discover them from keywords).
  3. Start a scraping job. Competitors are processed one by one in a real Chrome browser driven by Selenium; each profile's Updates are scrolled, expanded and extracted with their images and call-to-action buttons.
  4. Each post gets a fingerprint (Google post id, else post URL, else business + normalised text). Posts already in the repository are skipped and counted as duplicates.
  5. New posts are analysed: topic, sub-topic, keywords, content type, CTA and offer.
  6. Trends show which topics competitors use, how many of them, and how often.
  7. The generator writes ideas or complete updates from those trends and never repeats earlier ideas.

When Google asks for verification

If a CAPTCHA, "unusual traffic" or sign-in check appears, the job pauses (it never fails silently), the run and competitor are marked needs verification, and the run page shows a screenshot with Continue, Skip and Cancel. You can solve the challenge in the scraper's browser window, or click on the screenshot to solve it remotely. The intervention is recorded in the scrape log.

To reduce interruptions the scraper uses a persistent Chrome profile (cookies from a completed verification are reused), realistic pacing with random pauses, a single browser per run and English locale settings. It does not bypass Google's controls.

Demo data

The pre-loaded projects use a synthetic demo dataset of fictional businesses so the system can be evaluated even when Google blocks live scraping. Choose “Demo source” when scraping to replay the workflow: the second scrape finds new posts, later scrapes only duplicates. Choose “Live Google Maps” to scrape real profiles.
